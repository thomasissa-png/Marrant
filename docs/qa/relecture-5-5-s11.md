## Vérifié, pas de bug trouvé

- **client.ts** : aucun appelant ne passe `temperature`/`top_p`/`top_k` (refusés en 400 sur Sonnet 5.5) ni `thinking.budget_tokens` ; tous les appels passent par `callWithRetry`. `effort` valide (`low`…`max`, SDK 0.129 `OutputConfig`). Marge de réflexion +4000 tokens : max 12 000, sous le seuil non-streaming du SDK (~21 333). `getResponseText` filtre par type (blocs `thinking` ignorés), aucun `content[0]` restant. Refus : `stop_details.category` existe dans le SDK, non retenté, loggé une seule fois, pas d'alerte. Pas de boucle d'alerte (`sendAdminAlert` n'appelle pas le LLM).
- **usage-log.ts** : tarifs Sonnet 5.5 (2/10, cache 0,20/2,50) et Opus 5.5 (4/20, cache lecture 0,20, écriture 5) conformes à la grille publique Anthropic.
- **failure-alert.ts** : throttle 24 h par type via `JobLock` (clé unique, purge des verrous expirés), silencieux en cas d'échec.
- **startup-tasks.ts** : chaque tâche a son try/catch, `runStartupOnce` a le sien, rien ne bloque le boot. `applyBlogArticleRewritesTask` v2 : marqueur `DataPatch` écrit dans la même transaction que l'update, pas de marqueur si article absent ou non publié. Aucune correction `blog-article-fixes.json` ne réintroduit sa propre chaîne (pas de croissance à chaque boot). `weak-jokes.json` : 0 recoupement avec le seed et avec les `previousContent`. `joke-decryptages.json` couvre les 264 vannes du seed. 0 doublon de `content`, 0 alias égal à un `content` courant.
- **seed-data.ts** : alias `previousContent`/`previousTitle` restreints à `generatedByAI: false` ; désactivations vannes/conseils filtrées `generatedByAI: false` (désormais vidéos aussi).
- **Middleware** : inchangé ; `/api/health` n'est pas soumis à l'authentification.
- **Newsletter** : zod, rate limit par IP, tokens opaques de 32 octets, pas d'injection.
